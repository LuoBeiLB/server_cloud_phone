# 扩展功能模块

在主流程之上新增的模块（均已接入真机后端验证）。菜单顺序见左侧导航。

## 1. 数据看板（`/dashboard`）
- 后端 `backend/app/routers/metrics.py`：
  - `GET /api/metrics/overview` → `{total_devices, running, stopped, error, creating, total_groups, ws_clients, unique_exit_ips, by_group[], model_distribution[], recent_devices[]}`
  - `GET /api/metrics/devices` → 每台轻量行（含 model/exit_ip）
- 前端 `frontend/src/views/Dashboard.vue`：KPI tile + 状态分布分段条 + 机型/分组分布条 + 最近设备表，每 5s 自动刷新。
- 证据：`docs/screenshots/数据看板.png`

## 2. 告警监控（`/alerts`）
- 后端 `backend/app/routers/alerts.py`（**即时计算，无持久化/无后台任务**）：
  - `GET /api/alerts/current` → `{generated_at, total, by_level{critical,warning,info}, alerts[]}`
  - `GET /api/alerts/rules` → 规则清单（展示用）
  - 规则：设备异常→critical；已停止→info；运行中无出口 IP→warning；出口 IP 冲突→warning；缺 android_id→warning
- 前端 `frontend/src/views/Alerts.vue`：级别计数 + 告警表 + 规则折叠区，每 5s 刷新。

## 3. 任务调度（`/tasks`，计划 7.3）
- 后端 `backend/app/scheduler_models.py`（`ScheduledTask` 表，随 `init_db` 自动建表）+ `backend/app/routers/tasks.py`：
  - `GET/POST /api/tasks`、`GET/PATCH/DELETE /api/tasks/{id}`、`POST /api/tasks/{id}/run-now`
  - `schedule_type`：`once`(需 `run_at`) / `interval`(需 `interval_seconds`)；`action ∈ {open_url,tap,swipe,key,text,install}`，目标 `device_ids[]`
  - 后台 `scheduler_loop()`（在 `main.py` lifespan 启动）每 ~5s 扫描到期任务并执行；`interval` 自动续期，`once` 触发后停用。
- 前端 `frontend/src/views/Tasks.vue`：任务列表 + 创建对话框（选动作/参数/设备/调度）+ 启停开关 + 立即执行。
- 真机验证：interval 任务 `run-now` 驱动 2 台真机开网页 **2/2 成功**。

## 4. 设备详情聚合页（`/detail/:id`，计划 GM-003）
- 后端 `backend/app/routers/device_detail.py` + 编排层新增 `list_apps`：
  - `GET /api/devices/{id}/detail` → 设备行 + fingerprint + `uptime_seconds` + `installed_app_count`
  - `GET /api/devices/{id}/apps` → `{device_id, count, apps[]}`（redroid 走 `pm list packages`，simulator 返回 mock）
- 前端 `frontend/src/views/DeviceDetail.vue`：PhoneFrame 实时预览 + 运行概览 + 设备标识/浏览器指纹/网络 + 已装应用表。设备管理页「详情」按钮进入。
- 真机验证：真机 1 拉到 **97 个已装包**。

## 10. 高保真 iOS 皮肤（原创设计）

## 11. 一键换肤（皮肤主题引擎 + 真机落地）
- `preview.py` 内置主题注册表 `THEMES`：**3 套原创主题** iOS 风(`ios`)/暖阳渐变(`sunset`)/深色毛玻璃(`glass`)，差异体现在**壁纸取色板 + 图标底样式（渐变实底 ↔ 半透明毛玻璃）+ 圆角比例**，7 屏 × 3 主题 = 21 组皆可渲染。`render_frame(..., theme=)` 贯穿全部界面。
- 数据层：`Device.skin` 字段（默认 `ios`）+ `database.init_db` 幂等 `ALTER TABLE` 迁移（老库自动补列）；`DeviceOut`/详情接口输出 `skin`。
- 接口：`GET /api/skin/themes` 主题清单；`POST /api/skin/{id} {theme,apply_device}` 单台换肤；`POST /api/skin/batch {device_ids,theme,apply_device}`（`device_ids` 空=全部）批量换肤，写操作审计（`skin.apply`/`skin.apply_batch`）。

**换肤两步生效（hybrid，用户实时可见 + 真机最终一致）：**
1. **平台层即时（0 延迟）**：换肤即写 `device.skin`；`redroid.screenshot()` 对**主屏（未开网页）设备直接渲染主题皮肤**，`_preview_loop` 每帧按 `device.skin` 出图 → **多画面预览/投屏立即切主题**（浏览中的设备显示真实网页截屏不受影响）。
2. **真机系统级（后台落地 + 重启生效，`deploy/ios-skin/apply-ios-skin.sh` 验证流程的 API 移植）**：`POST` 后 fire-and-forget 后台任务调用 `backend.apply_skin(device, theme, progress)`；redroid 实现＝①装 **Lawnchair 1.2.0.1884**（`app/skins/lawnchair.apk`，官方 GitHub Releases 原版，克隆后经 `deploy/ios-skin/fetch-lawnchair.sh` 下载，缺失则降级为仅壁纸；已装则跳过）+ `pm grant` 存储权限（防首启弹窗）+ `cmd package set-home-activity` 设为默认桌面 → ②重排 `launcher.db`：应用铺进 **iOS 4 列网格 + Dock4**（get_archive 拉库→进程内 sqlite3 重写 favorites→put_archive 推回；容器内 sqlite3 会 abort 不能用）→ ③主题壁纸(`app/skins/wallpaper_{theme}.png`) put_archive 写 `/data/system/users/0/wallpaper` → ④**容器重启** + 轮询 `boot_completed` 回连 → ⑤开机后**合并** Lawnchair 偏好（4列/6行/Dock4 + squircle 圆角蒙版；必须在开机迁移后插入 `</map>` 前、String 型，整体覆盖会被重置）。多台**顺序**落地避免同时重启；`apply_device=false` 可只换预览不动真机。
- **redroid 硬约束（为何要重启）**：该镜像 `cmd wallpaper` 为空实现、AOSP 无 `adb set-wallpaper`，只重启 SystemUI 不重载壁纸（位图缓存在 system_server）→ 系统壁纸真的变只能改壁纸文件 + 整机重启。即时性由平台层承担，真机系统级由后台重启承担。
- **落地进度实时提示**：每步经 WS 广播 `skin_progress {device_id, phase, theme}`（phase=queued/launcher/grid/wallpaper/reboot/prefs/done/failed），`GET /api/skin/applying` 供页面加载时补齐；前端设备列表「皮肤」列与详情页应用按钮下实时显示（排队等待/装 iOS 启动器/布置 iOS 桌面/写入壁纸/**重启生效中**/配置主题/完成），终态展示 6s 自动消失。每台约 40–90 秒（首次含装启动器）。

**真机桌面 = 设计稿 1:1（多 agent 工作流完成）：**
- **设计稿图标上真机**：`deploy/ios-skin/gen-design-icons.py` 从 `preview.py` 同源渲染 3 主题 × 20 图标（Chrome 无头 SVG→PNG，256 RGBA，squircle 渐变 + 字形与预览像素同源）→ `app/skins/icons/{theme}/{NN}.png` + `manifest.json`；`orchestrator/ios_layout.py` 定义设计稿 20 条目布局表（16 主屏 + 4 Dock，中文标题；日历/照片/时钟/设置/文件/电话/Safari 映射真机组件，信息/地图/天气等映射可配置的移动站 URL）；`_populate_grid` 把全部条目写成 **favorites `itemType=1` 快捷方式 + 图标 BLOB**（真机探针验证：BLOB 像素级原样呈现、免疫图标形状开关、点击可跳转；资产缺失自动回退旧真实应用网格）。
- **壁纸按设备轮换**：`gen-theme-wallpapers.py` 复刻 `preview._wallpaper()` 渐变+柔光团，3 主题 × 3 取色板 = 9 张 `wallpaper_{theme}_{rid}.png`；`apply_skin` 用与预览相同的 rid 公式（fingerprint seed 求和取模）选档 —— 真机壁纸与预览渲染同款同色。
- **Dock 毛玻璃底板 + 页面圆点**：Lawnchair v1 无此功能，把底板/圆点**画进壁纸**（坐标按真机 hotseat 实测锚定），配合偏好 Dock 全透明 + 隐藏「^」箭头，视觉等效设计稿。

## 12. 通知栏 / 控制中心（操控页手势补全）
- 后端 `key` 动作新增 `notifications` / `quicksettings` / `collapse`，走 AOSP
  `cmd statusbar expand-notifications|expand-settings|collapse`。
- **为什么不用下滑手势**：操控页原「下滑」是 30%→80% 的页面滚动，起点没压在状态栏上，
  永远拉不出通知栏；而 `input swipe` 从顶端起手在启用 iOS 手势导航条后更易被吞。
  `cmd statusbar` 是正规入口，不依赖起点像素、幂等、立即生效。
- 前端操控页「通知栏 / 控制中心 / 收起」按钮组；原按钮改名「上滑滚动 / 下滑滚动」消除歧义。
- 真机验证：通知栏与快捷设置面板均正常拉出、收起。

## 13. 设备失联的显式化（健壮性，v1.1）
- 编排层 `_adb()` 区分「传输层错误（设备不可达）」与「命令本身失败」：
  前者**先自愈**（`adb connect` + 轮询就绪 ~2s），仍失败抛 `DeviceUnreachable`。
- `screenshot()` 增加 `_ensure_alive()` 前置体检（TTL 5s；取帧最高 12fps 不能每帧体检）。
  **注意**：主屏皮肤渲染那条分支原本根本不碰 adb，是故障最容易藏身的地方。
- 接口语义：设备失联 → **503**（带 `adb connect` 排障提示）；设备活着但命令失败
  （路径不存在/无权限等）→ **502**。`list_apps/list_logcat/list_files` 不再返回空列表
  伪装成「没有」。
- WS 新增 `device_unreachable` 消息；预览循环单台失败不再中断整条循环。
- 前端对 503 弹出「设备 N 已失联」提示（按 device_id 节流 10s）。
- 巡检：`backend/acceptance_live.py` §5 会检出「有画面但其实是失联」的伪装。
